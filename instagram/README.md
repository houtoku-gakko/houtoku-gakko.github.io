## フォルダの使い方

```
instagram/
├── README.md        … この文書（部署の全体像・運用フロー）
├── GUIDELINES.md    … 投稿ガイドライン（書き方・写真・個人情報の扱い）
├── TEMPLATE.md      … 投稿下書きのひな形
├── posts/           … これから投稿する下書き（1投稿＝1ファイル）
└── archive/         … 投稿し終えた下書き（記録として残す）
```

下書きのファイル名は `YYYY-MM-DD-内容.md` の形にします。
日付は「投稿する予定の日」です。

例：`posts/2026-05-24-taue.md`

## 運用フロー

1. **企画**
   `instagram/TEMPLATE.md` をコピーして `instagram/posts/` に新しいファイルを作る。
   Claude Code を使う場合は `/instagram-post` と打つと、ひな形の作成から
   本文の下書きまで担当エージェントが手伝います。

2. **下書き**
   本文・ハッシュタグ・使う写真を書く。
   書き方のルールは `GUIDELINES.md` を必ず確認する。

3. **確認（ここが「編集」の中心）**
   下書きの「確認チェック」欄を上から順に埋める。
   とくに **写真に写っている方の掲載許可** と **個人情報が写り込んでいないか** は、
   必ず人の目で確認する。AI の判断だけで通さない。

4. **最終承認**
   最終確認者（上の表の担当）が目を通し、下書きの「承認」欄に名前と日付を入れる。

5. **投稿**
   Instagram アプリ／ブラウザで実際に投稿する。
   この仕組みは下書きを管理するためのもので、自動投稿はしません。

6. **記録**
   投稿したら、ファイルの先頭の `status:` を `posted` に変え、
   投稿URLを書き入れて `instagram/archive/` へ移動する。

## この部署が扱わないこと

- 自動投稿・API連携（現時点では行いません）
- 参加者からのDM対応、コメント対応の方針（別途決める必要があります）
- サイト本体（index.html など）の更新
